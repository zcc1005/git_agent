# 智能体知识问答测试清单

下面 30 个问题用于验证“项目知识问答”，不会要求智能体启动、停止、确认或取消实际任务。建议新建一个对话后逐条提问，重点检查：

- 第一段是否直接回答当前问题，而不是罗列无关功能。
- 操作类问题是否给出不超过 5 条的可执行步骤。
- 原理类问题是否解释关键流程和限制。
- 不确定的信息是否明确说明证据不足，而不是猜测。
- 开发类问题是否能引用正确的代码文件或关键函数。

| 编号 | 分类 | 测试问题 | 期望回答要点 |
| --- | --- | --- | --- |
| 1 | 系统能力 | 这个系统目前能完成哪些主要工作？ | 概括图片/视频检测、监控巡检、报警、历史查询和报告，不展开无关细节 |
| 2 | 系统能力 | 图片检测、上传视频检测和实时巡检有什么区别？ | 说明输入来源、处理方式、持续时间和保存内容的区别 |
| 3 | 系统能力 | 从用户上传文件到对话框显示检测结果，完整流程是什么？ | 上传保存、检测、结果持久化、媒体 URL、前端展示 |
| 4 | 上传媒体 | 我上传的图片和视频保存在哪里？ | 保存到项目 outputs 下的对应目录，数据库只保存引用 |
| 5 | 上传媒体 | 上传的图片和视频会直接存进 SQLite 数据库吗？ | 不存二进制或 Base64，只存相对路径和元数据 |
| 6 | 上传媒体 | 同一个图片或视频重复上传会占两份空间吗？ | 内容哈希去重，相同内容复用一份文件 |
| 7 | 上传媒体 | 为什么本地能看到检测图片，部署到服务器后可能看不到？ | 路径、媒体文件迁移、持久化卷、反向代理 URL 等原因 |
| 8 | 上传媒体 | 容器重建以后，怎样保证历史对话里的图片还能显示？ | 持久化整个 outputs，不能删除命名卷 |
| 9 | 上传媒体 | 旧数据库里保存的是 Windows 绝对路径，服务器还能识别吗？ | 说明旧 outputs 路径会映射到当前部署，但实际文件必须存在 |
| 10 | 上传媒体 | 系统支持上传哪些图片和视频格式？ | 说明允许的常见图片及视频后缀，避免虚构格式 |
| 11 | 检测逻辑 | 图片检测完成后会生成哪些结果文件？ | 检测 JSON、可视化图片、统一报警和文本报告 |
| 12 | 检测逻辑 | 视频检测为什么只展示代表帧，而不是保存每一帧？ | 事件聚合、减少重复图片和存储占用 |
| 13 | 检测逻辑 | sample_fps 参数是什么意思，调高有什么影响？ | 每秒抽取检测帧数、精度/资源消耗权衡 |
| 14 | 检测逻辑 | conf 和 known_conf 分别控制什么？ | 通用/未知候选与已知类别确认阈值，按实际代码说明 |
| 15 | 检测逻辑 | unknown 异物和四个已知异物类别是怎么区分的？ | 模型类别、低置信候选和后处理规则 |
| 16 | 检测逻辑 | 系统如何避免同一个异物在连续视频帧里被重复计数？ | 去重、跟踪、事件沉默时间和事件聚合 |
| 17 | RTSP | RTSP 监控源需要在哪里配置，为什么不直接把地址写进聊天消息？ | 受控配置、source_id 映射和敏感信息保护 |
| 18 | RTSP | 检查监控是否在线和启动实时巡检有什么区别？ | 探测只检查连接；巡检持续取帧并检测 |
| 19 | RTSP | 周期巡检和持续实时巡检有什么区别？ | 分段采集调度与持续连接处理的区别 |
| 20 | RTSP | 持续实时巡检默认会保存完整视频吗？ | 默认保存事件代表帧，不保存完整视频；录像需单独归档 |
| 21 | RTSP | 监控流中断后系统会怎样处理？ | 连接状态、重连、错误记录和停止条件 |
| 22 | RTSP | 如何检测昨天某个时间段的历史录像？ | 必须先有录像归档，再按绝对时间范围检测 |
| 23 | 报警 | 风险等级和是否需要停机是由大模型决定的吗？ | 确定性规则负责，大模型只解释已有事实 |
| 24 | 报警 | 确认报警和取消报警分别会修改什么？ | 报警状态、控制记录和审计信息 |
| 25 | 报警 | 检测历史、报警历史和聊天记录分别保存在哪里？ | SQLite 中不同记录类型及 outputs 中的相关文件 |
| 26 | 报警 | 为什么检测到了候选异物，却不一定立即产生高风险报警？ | 确认阈值、类别、数量、事件和风险规则 |
| 27 | 部署 | Docker 部署时哪些目录必须持久化？ | outputs 必须持久化；模型权重按部署配置挂载 |
| 28 | 部署 | 模型权重路径如何配置，为什么不应该写死本机绝对路径？ | 环境变量和项目相对路径，容器与本机路径不同 |
| 29 | 开发实现 | 项目知识问答从收到消息到调用大模型的代码流程是什么？ | service 路由、knowledge 检索、llm answerer、证据约束 |
| 30 | 开发实现 | 如果智能体回答不切题，应该检查哪些代码和运行信息？ | 路由模式、answer_source、检索命中、索引刷新、LLM 初始化状态 |

每个问题可以记录以下内容：

```text
问题编号：
是否切题：是 / 否
是否易懂：是 / 否
是否包含错误事实：是 / 否
遗漏内容：
不相关内容：
你期望的回答：
```
